5. Optimization Objective — 🟡 IMPORTANT SCIENTIFIC AUDIT
The current objective is effectively a weighted combination of marginal risk reduction and lead-time savings:
w × risk + (1-w) × lead time
The source implements that directly. 
Problem
The units aren't naturally comparable.
A percentage point of risk reduction and a day of lead-time savings are fundamentally different quantities.
The UI treats the weighting parameter as the normalization mechanism.
That's usable as a prototype.
It is not yet a rigorous multi-objective optimization framework.
Rebuild
We should eventually normalize objectives or introduce an explicit utility/value function:

Risk Value
Lead-Time Value
Capital Cost
Strategic Value
Carbon Value
Optionality Value
↓
Decision Utility

This could become one of the biggest mathematical upgrades.
Disposition: 🟡 RESEARCH / REFORMULATE

7. Monte Carlo Engine
Status: 🟢 CORE ASSET / 🟡 SCIENTIFICALLY UNFINISHED
This is definitely not fake Monte Carlo.
It:
	1.	accepts a correlation matrix
	2.	attempts Cholesky decomposition
	3.	generates independent Gaussian variables
	4.	transforms them through the Cholesky matrix
	5.	applies correlated shocks
	6.	calculates simulated risk
	7.	returns P50/P90/std. dev.

The UI supports 1,000–50,000 iterations. 
But here is the forensic finding
The current shock model is:
1 + 0.12Z
with a floor of 0.4.
Those parameters are not yet scientifically justified. 
So:
The engine is real.
The stochastic model is provisional.
That's an important distinction.
Rebuild

/stochastic

DistributionModel
CorrelationModel
ShockModel
RegimeModel
ScenarioGenerator
MonteCarloRunner
TailRiskAnalyzer
ForecastEngine

Then calibrate the actual distributions.
